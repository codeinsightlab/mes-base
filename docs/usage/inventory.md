# 库存与单据审核

LOCAL仓库以正式库存动作和余额为权威。草稿、页面保存成功或外部接口接收成功，都不能直接代表库存已经生效。

## 单据生命周期

- 正式出入库单统一使用 `StockDocument` 主单与明细，材料领用使用`MATERIAL_ISSUE`。普通出库即使填写工单也不创建Execution或MES投入；只有MES扫码入口按固定组合和确认套数编排单据、审核与投入，详见[生产流程](production.md#扫码批次与库存来源)。
- `documentId` 是单据主表身份，`lineId` 是明细主键，行号由 `lineNo` 表达。生产投入事实通过 `mes_material_issue_input.document_id` 关联统一单据，保留逐次产出贡献和独立请求身份；材料收发数量归单据明细。BOM及冻结路径归工单与Execution，不横向复制进库存主表。
- 创建与审核使用独立请求身份；创建内容冲突拒绝，审核不能覆盖创建身份。草稿取消没有库存效果；生产领料撤回通过原库存动作的反向关联记录，不以取消草稿代替。
- 入库单与出库单是两个独立页面，分别使用固定IN的 `/api/wm/inbound-documents` 和固定OUT的 `/api/wm/outbound-documents`。类型、编号候选、列表、详情、聚合保存和审核沿各自方向；伪造方向或访问另一方向资源会被服务端拒绝。两方向复用同一主单、明细和库存实现。
- 普通单据一次聚合保存为草稿，再按仓储权限审核。MES领料权限不授予通用仓储创建或审核能力；生产入库及质量处置由MES业务调用仓储，再由各自业务服务检查生产收尾，仓储不反向调用MES命令。
- 领料、生产入库、不良/报废入仓等业务入口可提供“新增并审核”便捷操作，编排同一套单据与审核用例。
- 审核通过后，在同一LOCAL事务校验来源、权限、版本、数量和幂等，记录审核身份并执行库存动作。
- 审核生效单据不能通过普通编辑改写库存事实；合法订正、作废或恢复按各自正式接口及留痕规则执行。

已知原生产领料请求UUID时，可以只读恢复其统一单据：`GET /api/wm/outbound-documents/by-request/{requestId}`。单据页面支持`requestId`链接参数并转为正式`documentId`；恢复不取号、不重新审核或执行库存动作。它沿用当前工厂及原单据详情权限，仅返回领料单，未知或非领料UUID返回404，不返回冻结请求JSON和指纹。

## 来源与数量

MES领料使用工单全部实际需求、工单余额、材料单位、固定批次及实时库存，支持多行和重复库存来源，并在整单事务中控制共享余额。普通出库仍按库存合法性审核。MES正常入库按Execution累计可入量校验；已保存的生产入库单经MES审核入口处理。不良/报废入仓关联有效申报及处置，不能凭手填单号或类型名称绕过来源。

生产退料需指定原出库明细；仅单行旧单据允许省略明细ID。退料保留投入，不代表增加产能，后续MES配套计算扣除实际退料。整单撤销逐行关联原库存动作、扣除已退量后恢复库存，所有反向行共享一个撤销操作身份。已发生报工、质量及入库等下游事实时继续严格保护，不改写原事实。

同一Execution支持分批入库；每次审核重新检查累计剩余量，草稿不占作已生效入库。正常品和质量入库分别计量，审核后复用同一生产收尾规则。入报废品仓不代表已完成最终销毁或核销。

部分单据类型尚未接通正式来源，可以保留草稿但禁止审核；不以其他出入库类型代替缺失的采购、委外或退料来源链。

## LOCAL与ERP

工单、原材料仓与成品仓须符合持久化来源及当前模式。EXTERNAL库存镜像仅供参考，不能通过本地命令修改ERP权威库存；UNKNOWN保留原身份及冻结依据，交由授权人员核实。完整规则见[LOCAL/ERP边界](../architecture/local-erp-business-boundary.md)。

仓内后续流转属于仓储；生产退料按独立正式业务开放，不通过通用调拨改变生产投入。

## 统一领料结构升级

结构准备、事实转换与旧结构退役分阶段执行。已有旧领料事实的环境通过受控的一次性转换复用已有统一单据，以数据库生成的新身份关联其余单据；转换直接映射已发生事实，不调用业务创建、审核或库存接口重新生效。缺少历史BOM身份不阻断已发生的材料收发及生产贡献转换，也不能据此猜测BOM、重算历史或重新扣库。

投入表保留有意义的生产事实、原UUID和独立指纹；业务发生时间独立于请求建立及库存动作时间。旧主单、明细、ERP扩展和提交封套在引用切换与事实核对完成后退役，不保留另一套领料主单。既有统一单据保留自己的编号和审计事实；退役结构的纯过程审计证据不参与运行期业务计算。

转换核对包括唯一主明细映射、原请求身份及指纹、逐条业务时间、原库存和反向动作关联、库存余额不变，以及由正式目标结构独立计算的逐Execution、工单有效投入等价。先停写，再升级结构、转换并核对，完成退役后加载匹配版本；不得先加载依赖尚不存在字段的制品，也不得让自动迁移越过待转换环境的退役守卫。任何检查失败均停止对应退役；MySQL结构变更不能依赖事务回滚恢复，禁止用repair或baseline跳过失败。

当前整单撤回能力以具体业务入口为准。底层已有反向动作不代表所有类型均支持POSTED整单撤销；部分退料和未接通来源的撤回不能通过任意库存类型绕过业务校验。

## 同步库存调拨

库存调拨页面与 `/api/wm/stock-transfers` 表达一个完整调拨业务。一次保存形成关联的调拨出库单（TRANSFER_ISSUE）与调拨入库单（TRANSFER_RECEIPT），双单按明细行号对应；类型业务key也是各自自动编码ruleCode，显示名称来自当前业务字典。既有规则、计数与历史单号不因类型增加而覆盖。新规则每日从001开始，各厂独立，超过999自然增长。

当前开放同厂LOCAL仓库或库位之间同步调拨，源库存选择已有正式身份；目标选择LOCAL仓库和可选库位，也可指定已有目标库存。目标物料、基本单位与批次继承源库存并保持不变。不同库存记录必须属于不同仓库或库位；源集合与目标集合不能交叉。禁用身份、混合来源、不足数量及非法精度拒绝。目标身份尚不存在时，保存草稿在同一事务内复用正式库存创建能力建立零余额身份，无库存动作；同身份后续复用。新身份与草稿任一步失败整体回滚，取消草稿不改变余额。目标仓库必须已经存在且可用，不能手填目标物料或批次制造新身份。

草稿一次聚合保存主单与明细，修改和取消同时处理双单，取消不改变库存。审核在同一本厂LOCAL事务内校验并锁定库存，扣减全部源库存后增加全部目标库存，双边单据与动作原子生效；任何一行失败整体回滚，不产生单边过账。普通入库、出库页面只能查看调拨单，不允许单边修改、审核或取消。

创建UUID与审核UUID独立。同一创建请求返回原双单，内容冲突拒绝；编辑提供原创建UUID及当前出库主单版本。审核重复请求返回原结果，版本或身份冲突拒绝。出库审核保存原UUID，入库审核使用其确定性派生UUID；每边库存动作关联各自主单审核身份，双单关联提供完整追溯。已审核调拨不能普通编辑或取消；当前不提供通用已过账调拨整单撤销、分步签收、在途库存、跨厂或ERP调拨。
