# 生产流程

## 基本对象

工单表达当前产品的单阶段生产需求；Execution承载一个生产批次的实际投入、锁定路径、报工、不良和入库事实。材料组合码首次成功领料建立Execution及独立产出批次；未结束时同码追加复用Execution，结束后禁止重开。

工单保存只创建或修改工单需求；旧 `batches` 请求字段属于非法字段并返回 `BAD_REQUEST`。保存工单不会创建投入、Execution、执行路径或库存事实。旧工单批次和路径业务已退役，当前产品不再提供对应查询接口、页面或权限；当前批次及实际路径以正式 Execution 为准。历史操作记录和生产事实仍按各自当前查询能力读取，不恢复旧工单批次模型。

工艺路线通过物料ID关联适用产品；BOM通过产出物料ID关联标准组件，两种关系分别表达加工方法与用料组成。工艺适用产品关系只保存物料ID，详情经统一业务目录缓存取得当前物料编码和名称，不另存产品编码、名称快照。当前物料资料缺失时保留关联ID并标明待确认。工序发布快照与生产事实保持各自语义。

## 单阶段工单与用料

工单维护单阶段需求，领料和执行分别记录实际材料流转及产出批次。生产规划、MES扫码领料和通用仓储出库具有独立职责。

| 对象 | 职责 |
| --- | --- |
| 工单及用料明细 | 当前产出物料、计划数量、所选BOM版本、直接材料及需求数量；不分配原料库存或批次，不保存产出批次 |
| 领料出库明细 | 实际物料、库存身份、仓库/库位、原料批次、单位及实领数量；同一组件可分配多个批次，各组件可来自不同批次 |
| Execution | 独立的产出批次、实际投入及生产事实；原料批次通过正式领料/投入关联追溯，不从任意原料行推导产出批次 |

每个产品可以在已发布BOM版本中设置一个默认版本，也可以暂不设置。工单创建/编辑选择产品时，有默认则预选默认已发布版本，仍可改选同产品其他已发布版本；没有默认则必须由用户选择，即使只有一个候选也不私选。工单关联确切版本，保存时复验版本身份及内容修订号。默认标记不改变BOM组成或版本身份，默认切换或停用不会改写已保存工单、冻结依据及生产/库存事实。

选定版本后，以根版本的全部直接组件生成初始明细：`标准需求量 = 工单计划产出量 × 组件用量 ÷ BOM基数`。用户可以增加材料或修改工单明细，实际采用量与BOM标准依据分清，调整只作用于当前工单。计划产量改变时，未调整的BOM行重新计算；手动调整及新增行保留实际数量，并在保存前提示用户确认。切换产品或版本不能无提示覆盖人工调整。

单阶段生产只核对当前产出、直接组件、当前产出适用工艺及合法可用库存；组件已有可用库存时按正式来源、身份、单位和数量规则领用，不要求它们重新开工单制造。下层BOM、组件自身工艺和整棵BOM的父子履约不构成当前阶段的额外准入条件。缺少当前产出适用工艺仍是现有流程的阻断，不能据此推断委外或补造工艺、报工。

### 保存与存储边界

`workorder`保存单头、确切BOM及内容修订号、用料整体修订号、允许仓库、工作中心和固定时间；原`mes_workorder_material`通过`workorder_id`保存多行材料，`id`是独立明细身份。明细保存BOM来源行、标准比例、计划依据、实际需求和人工调整标记，标准需求由这些依据计算，不新增第三张用料表。

创建/编辑工单通过`POST/PUT /api/production/workorder`一次提交单头及`material`对象。后端在同一事务中保存单头和完整明细，复验选定BOM及revision、明细归属、全部直接组件、材料基本单位和数量精度；任一失败整体回滚。创建使用`workorder:create`；整单编辑还须具备`workorder:update`和`workorder:material:update`。首次正式投入固定用料后禁止改写。

工作中心和允许仓库可以暂不配置；若已配置允许仓库，分配遵守该范围与来源约束，未配置时使用当前工厂合法启用的LOCAL仓库。二维码不保存或冻结库存位置。详情中的`GET/PUT /api/production/workorder/{id}/material`读取或整体维护相同的用料配置及多明细，复用同一保存规则；其响应为配置和`items`，不再把单条材料当作整个工单。

带料复用`MaterialBomService`的版本读取及比例计算；`GET /api/basic/material-bom/{id}/direct-components?quantity=...`按物料查询权限返回已发布根版本及直接组件的标准需求，不遍历子BOM，也不要求下层制造。前端创建与维护共用选择和用料组件；服务端保存重新核实数据，不信任客户端提交的标准值。

MES领料按全部实际需求行计算，支持多材料、同材料多批次及多库位分配；人工调整行使用实际需求，不重新读取共享BOM覆盖它。原料批次与Execution产出批次独立。

V79保留存量明细主键、数量和已有业务事实，并将工单级配置归入单头；V79.1修正原字段的批次及标准/实际需求注释，不修改字段值。原明细表的`warehouse_ids/work_center/revision/status/bom_id/frozen_at`未删除，保留迁移前快照；正式用料、领料及引用校验不再以这些列为配置权威。内部只读原表查询仍可能读取快照；各部署加载新代码且完成消费者核对后，须另行通过正式迁移清理，不建立双写或库存事实重放。

## 执行路径的职责与维护边界

`mes_execution_path` 保存每个 Execution 的当前实际路径，主键就是 executionId；记录确切工艺版本、选择修订号以及 SELECTED/LOCKED 状态。`mes_execution_path_node` 保存该路径有序的工艺节点引用，节点身份不是工序身份，同一工序可以在不同节点出现。工艺图定义允许的加工路线，执行路径记录当前批次实际选择，两者不能互相替代。

路径通过 Execution 业务动作选择，正式投入确认时锁定；报工按路径校验前后节点，数量查询按末道节点计算产出，质量处理和收尾复用同一路径。两表是正式业务结构，不能随旧工单批次或导入辅助表一起退役，也不提供独立单表 CRUD 维护。底层 Entity、Example 和 Mapper 仍供正式业务服务使用。

一次性转换验收完成后，库内转换归档副本由 V78 退役；转换前原行及删除审计证据独立保存在受保护的库外备份中。新环境升级不保留运行期归档表或历史验收入口，正式生产查询仅使用当前业务事实。执行退役前须核实完整备份、校验和、恢复能力及数据库消费者，不能删除唯一原始证据或改写已发布迁移。

## LOCAL主流程

1. 准备物料、基本单位、已发布BOM、工艺路线及可领用库存。
2. 保存并下达单阶段工单。在“材料组合码”输入希望规划的产出量，计算、生成或复用二维码并打印。草稿工单也可规划；打印不建立执行、不预占库存或计划、不领料、不产生投入。
3. “扫码生产领料”读取固定组合和实时库存，默认最大完整配套量，用户可调小并重新计算。确认后，MES在同一LOCAL事务中创建或复用Execution、选择并锁定路径、创建多行`MATERIAL_ISSUE`并审核库存、记录正式投入。首次失败不留下空执行或部分扣料；相同UUID只生效一次。本次数量表示产出套数，各材料使用工单实际需求比例。
4. 按锁定实际路径提交完成报工；不良独立申报，不用修改正常报工来替代申报。
5. 正常品、不良品或报废品通过各自来源的正式入库审核交接。支持在剩余可入数量内分批入库。
6. MES入库或质量处置成功后检查Execution及工单收尾；报工和管理员订正不另行触发自动完结。

普通仓储单据保留先草稿、后审核的行为。管理员普通`MATERIAL_ISSUE`出库，即使关联工单，也不创建执行或增加MES正式投入，不自动并入MES。MES复用同一仓储审核与库存核心，仓储不会反向触发MES命令。详见[库存规则](inventory.md)。

## 扫码、批次与库存来源

组合身份为“工单＋稳定需求行＋各行原料批次集合”。材料按BOM需求行和人工行保存顺序排列；同品号在不同行仍保留行身份。批次去重并按原文稳定排序，不改大小写、空白或前导零。无批次库存保持null，不制造批次。需求依据修订和规范化指纹受数据库唯一约束。

载荷为`COMB:<FactoryId>:<组合记录ID>`。FactoryId避免分库ID相同导致串码，不授予访问权限。规则集中于`ProductionCombinationRules`。打印数量、库存余额、仓库、库位、库存ID和打印次数不参与组合身份。同工单、同需求依据和同组合复用同一码；工单“材料组合码”可以查询已有码并补印。已结束码只允许追溯和补印，不能恢复生产。

扫描只在固定批次内，按当前合法仓库、库位和共享库存余额分配。同品号多需求行不能重复使用库存。当前上限同时受固定组合库存、工单剩余额度、执行状态、单位精度及来源约束限制。本次材料量采用累计差额：`按实际需求比例计算(累计正式投入＋本次套数)－该需求行有效领料净量`，保留六位精度及累计舍入余数。部分退料不增加投入，后续计算扣除退料事实。出库量不冒充真实消耗；未记录消耗时不能填零。

提交重新校验；用户数量无法满足时返回`PRODUCTION_COMBINATION_STOCK_CHANGED`及最新`maximumQty`，不降低数量、不替换批次、不重新全局优化。用户可重新确认较小数量；计划员可主动重新规划其他组合，或正式调拨补充指定批次后继续使用原码。

首笔成功时Execution获得一次生成的独立产出批次；正式出库行保留需求行、物料、批次、仓库、库位、数量和库存流水。新领料仅接受组合码。已存在Execution的`工单号:品号#批次原文`保留精确查询能力，不用于创建领料。报工、质量等用户扫码统一经公共扫码入口定位已建立的Execution；内部详情、刷新使用executionId。扫码行为日志不是生产事实。

### 接口与计算范围

| 用途 | 接口 |
| --- | --- |
| 计算并生成或复用 | `POST /api/production/combinations`，传`workorderId`、`quantity` |
| 只读查询及补印 | `GET /api/production/combinations/resolve?code=...`、`GET /{id}`、`GET /{id}/qr` |
| 固定组合配套 | `GET /api/production/combinations/calculate?code=...&quantity=...`；省略quantity默认最大量 |
| 工艺预览 | `GET /api/production/input/preview?code=...&workorderId=...` |
| MES领料确认 | `POST /api/production/input`，传UUID、码、本次套数、工艺路径及计算依据 |
| MES审核已保存的生产入库单 | `POST /api/production/inbound-documents/{id}/actions/approve` |

组合及扫码领料复用`business:mes:material:issue:update`。普通单据审核仍需仓储post权限。旧`/api/production/input/drafts`及单材料库存查询、计算入口退役；原请求可经仓储`by-request/{UUID}`只读核实，冻结事实不重写。

计算在产出单位合法网格上二分最大配套量，以整数容量残余流验证共享库存；按材料优先选容量较大的批次，减少原料批次数。允许一组包含多批次，因此无其他拆分约束时，一个非空组合已达到最少码数。同批次内优先多材料共有的仓库，再按仓库、可用量、库存ID稳定分配。仓库成本是启发式，不宣称整体全局最优；扫码不选择码外批次。

单次最多100需求行、2000库存位置、20000需求与批次连接、100条出库明细；每次规划另限500万图操作。Edmonds–Karp单次理论复杂度`O(V×E²)`，二分约`O(log U)`次，单位网格校正最多10000次。超过预算明确拒绝，不截断需求或返回伪最优解。已有仓库来源、启用状态、可用余额和单位规则为硬约束；新增强制分配策略必须先接入可行集，不能被成本优化覆盖。

### BOM版本维护

物料BOM的已发布版本不可直接修改。在版本列表或详情选择“复制为草稿”，填写新的版本号后，系统在同一事务中复制原版本的基准数量、备注和全部直接组件，包括组件用量、单位、顺序和明确引用的子BOM版本；原版本不改变。新版本不发布、不设为默认，用户可维护草稿并通过发布操作执行现有完整校验。复制需要物料查询和新增权限，并核对来源版本修订号；版本冲突或明细复制失败时整笔失败。

停用的已发布版本可以启用；启用时重新校验物料、单位、组件和子BOM，校验通过后恢复为已发布版本，但不会自动设为默认。草稿及无效修订不能启用。

### 按物料编码逐层展开BOM

前端入口为物料管理工具栏的“物料BOM展开”及 `/basic/bom-explosion`。中心V57提供基础资料下的同名菜单定义，复用 `business:material:query`，不自动分配角色；需要侧栏入口时，由管理员通过现有角色授权入口分配。直接访问页面及接口仍校验当前工厂权限。

`GET /api/basic/material-bom/explode?materialCode=...&quantity=1` 使用当前工厂和物料查询权限，返回根物料、BOM版本候选、分支树及叶料汇总。可传 `bomId` 明确根版本，`versionOffset/versionLimit` 分页查询版本候选（默认0/20，最多100条）；分支树按请求规模限制一次展开，不以候选分页截断结构。

版本候选包含当前物料所有状态的版本；只有一个版本时可直接展开，存在多个版本时返回 `selectionRequired=true` 和 `MATERIAL_BOM_AMBIGUOUS`，用户明确选择后继续，不根据默认标记、状态或版本先后私选。指定版本必须属于输入物料；物料不存在返回404。

每层仅沿明确的 `child_bom_id` 递归，空引用表示结构中的叶项，不按组件物料的其他BOM自动补层。节点保留 `path/level/lineId/parentBomId/parentBomVersion`、物料与单位、`componentQty/baseQty/quantity`、`childBomId/leaf/children`。累计需求按各层“父需求×组件用量÷该层基数”计算，中间不按显示精度舍入。共享子版本可以只加载一次，但每条分支分别计算；叶料汇总保留全部贡献路径 `paths`，ID和数量为字符串。

`complete=true` 且无阻断时，叶料汇总才是该根版本的完整结构需求。缺少根或子版本、循环、非法基数／用量或身份不一致时，`problems` 返回明确路径、版本、明细、错误码和原因；可读原始节点与其他独立分支继续返回，无法可靠计算的数量为null。`complete=false` 时 `totals` 只包含已证明的叶项需求，不能当作完整总需求。超过层数或规模预算时明确返回 `MATERIAL_BOM_BUDGET`，不返回截断树或截断汇总。

此接口是结构查询，不创建工单、委外、履约、领料、报工、入库或库存事实，也不证明任何物料已经制造或可领用。

工单带料复用此服务的版本读取与数量计算，但使用根版本的直接组件；本页用于分析的全状态版本候选和歧义选择规则，不替代工单“已发布版本、默认优先、无默认由用户选择”的规则。递归分支不完整也不等于当前阶段的直接材料需求非法。

### 子件正式制造入库来源

`GET /api/production/input/manufactured-sources?workorderId=...&offset=0&limit=20` 使用当前工厂和生产领料权限，查询当前工单直接组件对应的正式制造入库记录。每页最多100条，返回 `items/total/offset/limit`；ID及数量均为字符串。

这是特定制造来源的辅助查询，不是普通领料的库存候选全集或单阶段投产门禁。查询沿工单已选BOM中明确的 `child_bom_id` 匹配子工单冻结的用料版本，不选择默认或最新子版本。当前该查询仅支持单直接组件；没有明确子版本时返回 `STOCK_DOCUMENT_SOURCE_PENDING`，多组件继续拒绝。这些限制只说明该查询的适用范围，不要求直接材料必须来自子工单制造；它不创建工单、履约分配或库存动作。

来源必须具有已审核的 `PRODUCTION_RECEIPT` 主单、明细、库存动作和一致的子Execution／工单／BOM身份。仅报工、未审核草稿、`OTHER_RECEIPT` 或来源未接通的 `OUTSOURCE_RECEIPT` 不构成该来源。结果同时校验材料、基本单位、批次、库位、允许仓库、LOCAL来源和当前可用库存。

每行保留 `documentId/lineId/stockActionId/executionId/workorderId/bomId/stockId`，便于核对正式事实。`receivedQty` 是该明细的已收数量；`stockAvailableQty` 是对应库存当前共享可用量。同一库存的多条入库明细会重复显示共享可用量，不能相加，也不能当作该入库明细的剩余履约额度。来源查询不会替代正式领料时的余额、身份、单位及事务校验。

该查询不证明整棵BOM已履约，也不要求为单阶段生产新增递归父子分配或上下级工单编排。普通领料仍按当前工单需求和合法可用库存校验。没有工艺不能推断为委外；委外收货属于独立业务契约，未接通的来源不能用其他入库或虚拟报工冒充。

## 数量与收尾

实物数量按物料基本单位的配置校验：单位可要求整数，或允许0—6位小数；不能根据单位名称推定规则，也不会通过舍入接受超精度输入。销售订单的订购数量与生产计划的计划数量同样必须为正数，并在正式保存时复验物料单位规则。BOM配比系数表达比例，不等同于实物数量。

设I为正式投入产出量、G为末道有效净产出、D为有效净不良损失、R为正常品审核净入库、Q为已申报不良对应的正式质量入仓量：

- Execution需满足 `I = G + D`、`R = G`，所有有效不良完成正式入仓，且原有路径、来源、未决操作和数量门禁通过。
- 工单的有效Execution均完全入库，且 `Σ(R + D) = 工单计划量`，才能完结。
- Q证明交接，不再次计入生产贡献；不累加各道报工来代表完工量。

例如投入100、有效不良10、末道净产出90，正常入库90、不良入仓10，工单贡献100。全不良允许由质量入库审核触发收尾，不创建零数量正常入库单。

未结束Execution可在工单余额内同码追加投入。结束后不可继续领料或重开；旧报工、质量、入库及结束事实保持不变。

## 不良数量与处理记录

当前质量数量按申报最新有效版本及其对应版本的处理事实计算；旧版本、作废申报和无关历史不计入当前数量。历史处理记录独立分页展示，历史累计条数不作为当前数量计算的准入条件。

不良详情的基本信息、当前汇总、处理记录和申报版本分别加载及重试。某一区域读取失败时，其他已授权且成功取得的记录和分页仍可查看。未知动作、重复核实或不一致数量保留原记录，无法可靠解释的派生字段显示待确认；相关新处理继续受严格校验约束。

结果未知的核实或入仓请求须保留原UUID与完整内容，按原申报、操作者、动作及内容精确核对。历史第一页未出现该UUID或核对返回未找到，都不能证明请求从未发送，也不授权生成新UUID重建。

## 异常与边界

未知提交结果保留原请求身份核实，不重新生成请求追加事实。局部派生查询失败时，已授权的原始记录仍可读，数量待确认；写入和收尾继续严格校验。不良仅负责申报与入仓，入仓后物流由仓储处理，不建设专门返工流程。

## 正式生产事实与旧导入结构退役

生产投入以已审核领料单关联的 `mes_material_issue_input` 为依据，报工及订正以 `mes_production_report` 不可变流水为依据，不良以当前正式申报与处理事实为依据。正常列表、详情、数量、流转和收尾不读取旧导入 JSON，也不依赖导入批次状态、规则版本或批准范围。

外部事实须先通过受控的一次性转换落入这些正式结构，核对数量、人员身份、引用及去重结果，再退役旧元数据。一次性工具不注册为应用服务、HTTP、定时或启动入口，不调用业务命令重放审核、领料或库存副作用。个别环境的补建单据、人员分摊及库存补偿须有明确授权和独立回执，不成为日常业务的兼容分支。
