# 生产流程

## 基本对象

工单表达产品、计划数量和工艺要求；Execution承载一个生产批次的实际投入、锁定路径、报工、不良和入库事实。同工单的新批次建立新Execution，同批追加复用既有Execution。

工单保存只创建或修改工单需求；旧 `batches` 请求字段属于非法字段并返回 `BAD_REQUEST`。保存工单不会创建投入、Execution、执行路径或库存事实。旧工单批次和路径业务已退役，当前产品不再提供对应查询接口、页面或权限；当前批次及实际路径以正式 Execution 为准。历史操作记录和生产事实仍按各自当前查询能力读取，不恢复旧工单批次模型。

工艺路线通过物料ID关联适用产品；BOM通过产出物料ID关联标准组件，两种关系分别表达加工方法与用料组成。工艺适用产品关系只保存物料ID，详情经统一业务目录缓存取得当前物料编码和名称，不另存产品编码、名称快照。当前物料资料缺失时保留关联ID并标明待确认。工序发布快照与生产事实保持各自语义。

每个产品可以在已发布BOM版本中设置一个默认版本，也可以暂不设置。默认版本只用于工单首次维护用料时的表单预选；用户仍可选择该产品的其他已发布版本。默认标记是产品的选择偏好，不改变BOM组成、版本身份或内容修订号。默认切换或停用不会改写已保存的工单用料、冻结依据或任何生产/库存事实。没有默认版本时由用户明确选择，不按版本号或创建顺序推测。

## 执行路径的职责与维护边界

`mes_execution_path` 保存每个 Execution 的当前实际路径，主键就是 executionId；记录确切工艺版本、选择修订号以及 SELECTED/LOCKED 状态。`mes_execution_path_node` 保存该路径有序的工艺节点引用，节点身份不是工序身份，同一工序可以在不同节点出现。工艺图定义允许的加工路线，执行路径记录当前批次实际选择，两者不能互相替代。

路径通过 Execution 业务动作选择，正式投入确认时锁定；报工按路径校验前后节点，数量查询按末道节点计算产出，质量处理和收尾复用同一路径。两表是正式业务结构，不能随旧工单批次或导入辅助表一起退役，也不提供独立单表 CRUD 维护。底层 Entity、Example 和 Mapper 仍供正式业务服务使用。

一次性转换验收完成后，库内转换归档副本由 V78 退役；转换前原行及删除审计证据独立保存在受保护的库外备份中。新环境升级不保留运行期归档表或历史验收入口，正式生产查询仅使用当前业务事实。执行退役前须核实完整备份、校验和、恢复能力及数据库消费者，不能删除唯一原始证据或改写已发布迁移。

## LOCAL主流程

1. 准备物料、基本单位、已发布BOM、工艺路线及可领用库存。
2. 下达工单并确定用料依据、工作中心和允许领料仓库。
3. 生产投入场景保存为统一出入库单草稿，单据类型为 `MATERIAL_ISSUE`；审核成功后创建或追加Execution投入。单据主身份使用 `documentId`，明细身份使用 `lineId`，生产投入事实按统一单据身份关联。当前生产只支持BOM的一条直接材料组件，数量按材料/产出基本单位及累计比例计算，不超工单剩余额度。
4. 按锁定实际路径提交完成报工；不良独立申报，不用修改正常报工来替代申报。
5. 正常品、不良品或报废品通过各自来源的正式入库审核交接。支持在剩余可入数量内分批入库。
6. 入库审核后检查Execution及工单收尾；报工和管理员订正不另行触发自动完结。

业务便捷入口可以编排新增、明细和审核，仍复用同一审核与库存核心；普通管理单据先保存草稿，之后独立审核。详见[库存规则](inventory.md)。

## 扫码、批次与库存来源

码采用 `工单号:品号#批次原文`；执行定位与材料领料各按正式业务身份校验，统一解析，调用方不自行规范化批次。已有Execution详情或内部刷新使用executionId，不制造新扫码或生产事实。

材料与产出沿用流转批次。多个可用仓库/库位候选由用户选择，只有一个候选时可直接选中；不能根据码中材料信息越过来源、单位、库存或BOM校验。

### 按物料编码逐层展开BOM

前端入口为物料管理工具栏的“物料BOM展开”及 `/basic/bom-explosion`。中心V57提供基础资料下的同名菜单定义，复用 `business:material:query`，不自动分配角色；需要侧栏入口时，由管理员通过现有角色授权入口分配。直接访问页面及接口仍校验当前工厂权限。

`GET /api/basic/material-bom/explode?materialCode=...&quantity=1` 使用当前工厂和物料查询权限，返回根物料、BOM版本候选、分支树及叶料汇总。可传 `bomId` 明确根版本，`versionOffset/versionLimit` 分页查询版本候选（默认0/20，最多100条）；分支树按请求规模限制一次展开，不以候选分页截断结构。

版本候选包含当前物料所有状态的版本；只有一个版本时可直接展开，存在多个版本时返回 `selectionRequired=true` 和 `MATERIAL_BOM_AMBIGUOUS`，用户明确选择后继续，不根据默认标记、状态或版本先后私选。指定版本必须属于输入物料；物料不存在返回404。

每层仅沿明确的 `child_bom_id` 递归，空引用表示结构中的叶项，不按组件物料的其他BOM自动补层。节点保留 `path/level/lineId/parentBomId/parentBomVersion`、物料与单位、`componentQty/baseQty/quantity`、`childBomId/leaf/children`。累计需求按各层“父需求×组件用量÷该层基数”计算，中间不按显示精度舍入。共享子版本可以只加载一次，但每条分支分别计算；叶料汇总保留全部贡献路径 `paths`，ID和数量为字符串。

`complete=true` 且无阻断时，叶料汇总才是该根版本的完整结构需求。缺少根或子版本、循环、非法基数／用量或身份不一致时，`problems` 返回明确路径、版本、明细、错误码和原因；可读原始节点与其他独立分支继续返回，无法可靠计算的数量为null。`complete=false` 时 `totals` 只包含已证明的叶项需求，不能当作完整总需求。超过层数或规模预算时明确返回 `MATERIAL_BOM_BUDGET`，不返回截断树或截断汇总。

此接口是结构查询，不创建工单、委外、履约、领料、报工、入库或库存事实，也不证明任何物料已经制造或可领用。

### 子件正式制造入库来源

`GET /api/production/input/manufactured-sources?workorderId=...&offset=0&limit=20` 使用当前工厂和生产领料权限，查询当前工单直接组件对应的正式制造入库记录。每页最多100条，返回 `items/total/offset/limit`；ID及数量均为字符串。

查询沿工单已选BOM中明确的 `child_bom_id` 匹配子工单冻结的用料版本，不选择默认或最新子版本。当前沿用单直接组件的投产边界；没有明确子版本时返回 `STOCK_DOCUMENT_SOURCE_PENDING`，多组件继续拒绝。它只发现来源，不创建工单、履约分配或库存动作。

来源必须具有已审核的 `PRODUCTION_RECEIPT` 主单、明细、库存动作和一致的子Execution／工单／BOM身份。仅报工、未审核草稿、`OTHER_RECEIPT` 或来源未接通的 `OUTSOURCE_RECEIPT` 不构成该来源。结果同时校验材料、基本单位、批次、库位、允许仓库、LOCAL来源和当前可用库存。

每行保留 `documentId/lineId/stockActionId/executionId/workorderId/bomId/stockId`，便于核对正式事实。`receivedQty` 是该明细的已收数量；`stockAvailableQty` 是对应库存当前共享可用量。同一库存的多条入库明细会重复显示共享可用量，不能相加，也不能当作该入库明细的剩余履约额度。来源查询不会替代正式领料时的余额、身份、单位及事务校验。

多层单材料制造可以分别通过子件正式入库、父件正式领用及制造入库逐层处理。现有领料命令尚未将上述入库明细保存为父子履约分配，来源查询也未成为全部领料入口的强制门禁，因此它不能证明整棵BOM已履约。完整闭环仍需多组件原子领料、递归父子数量分配及撤销保护；无工艺节点的正式委外还需订单、供应商、发料、损耗、退料和收货契约，不能用其他入库补齐。

## 数量与收尾

实物数量按物料基本单位的配置校验：单位可要求整数，或允许0—6位小数；不能根据单位名称推定规则，也不会通过舍入接受超精度输入。销售订单的订购数量与生产计划的计划数量同样必须为正数，并在正式保存时复验物料单位规则。BOM配比系数表达比例，不等同于实物数量。

设I为正式投入产出量、G为末道有效净产出、D为有效净不良损失、R为正常品审核净入库、Q为已申报不良对应的正式质量入仓量：

- Execution需满足 `I = G + D`、`R = G`，所有有效不良完成正式入仓，且原有路径、来源、未决操作和数量门禁通过。
- 工单的有效Execution均完全入库，且 `Σ(R + D) = 工单计划量`，才能完结。
- Q证明交接，不再次计入生产贡献；不累加各道报工来代表完工量。

例如投入100、有效不良10、末道净产出90，正常入库90、不良入仓10，工单贡献100。全不良允许由质量入库审核触发收尾，不创建零数量正常入库单。

同批追加可在允许的工单状态与余额内恢复Execution运行，保留旧报工、入库、结束时间和事实；不覆盖历史来伪造首次完结。

## 不良数量与处理记录

当前质量数量按申报最新有效版本及其对应版本的处理事实计算；旧版本、作废申报和无关历史不计入当前数量。历史处理记录独立分页展示，历史累计条数不作为当前数量计算的准入条件。

不良详情的基本信息、当前汇总、处理记录和申报版本分别加载及重试。某一区域读取失败时，其他已授权且成功取得的记录和分页仍可查看。未知动作、重复核实或不一致数量保留原记录，无法可靠解释的派生字段显示待确认；相关新处理继续受严格校验约束。

结果未知的核实或入仓请求须保留原UUID与完整内容，按原申报、操作者、动作及内容精确核对。历史第一页未出现该UUID或核对返回未找到，都不能证明请求从未发送，也不授权生成新UUID重建。

## 异常与边界

未知提交结果保留原请求身份核实，不重新生成请求追加事实。局部派生查询失败时，已授权的原始记录仍可读，数量待确认；写入和收尾继续严格校验。不良仅负责申报与入仓，入仓后物流由仓储处理，不建设专门返工流程。

## 正式生产事实与旧导入结构退役

生产投入以已审核领料单关联的 `mes_material_issue_input` 为依据，报工及订正以 `mes_production_report` 不可变流水为依据，不良以当前正式申报与处理事实为依据。正常列表、详情、数量、流转和收尾不读取旧导入 JSON，也不依赖导入批次状态、规则版本或批准范围。

外部事实须先通过受控的一次性转换落入这些正式结构，核对数量、人员身份、引用及去重结果，再退役旧元数据。一次性工具不注册为应用服务、HTTP、定时或启动入口，不调用业务命令重放审核、领料或库存副作用。个别环境的补建单据、人员分摊及库存补偿须有明确授权和独立回执，不成为日常业务的兼容分支。

| 对象 | 处置与现行职责 |
| --- | --- |
| `mes_legacy_source_lock` | 旧导入来源锁，由 V68.1 退役，无现行业务消费者或独立权限 |
| `mes_legacy_source_mapping`、`mes_legacy_migration_batch` | 旧转换映射与批次，完成正式事实转换及库外证据保护后通过 V76 退役迁移移除；不再提供历史查询或数量补算能力 |
| `mes_production_conversion_archive` | 转换验收完成后通过 V78 移除库内副本，完整原行审计移交受保护库外备份；无运行期消费者 |
| `business:production:report:detail` | 保留，用于当前正式报工详情和调整记录；旧历史接口移除不撤销此权限 |

退役迁移遇到尚未落实等价正式事实的旧元数据、结构部分删除或残余数据库引用时明确拒绝，不能直接删除尚未正式转换的事实。执行前核实目标、当前运行制品、事实完整性和完整库外备份；旧消费者必须先切换。MySQL DDL 隐式提交，中断后核对对象和 Flyway 记录，按授权恢复，不能以 repair 隐藏部分执行。

已发布迁移保持原文。原始来源和转换回执受保护保存，不重新进入正式查询链路，也不提供再次导入的授权。
