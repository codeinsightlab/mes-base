# 主子单据交互

主子单据的正式保存入口由业务页面提供一个聚合 API。新建和编辑都提交主单与全部明细，服务端在同一事务中先保存主单，再保存归属该主单的明细；任一步失败都回滚整单。审核、取消和其他状态转换继续使用独立业务命令，不由草稿保存触发。

前端页面复用 `mes-base-ui/src/components/document/MasterDetailDocument.vue` 与 `DocumentFields.vue`。业务页面显式提供主单字段、明细字段、列表查询 API、`aggregateApi`、父子关系键、权限和领域校验。`aggregateApi.detail/create/update` 分别读取或一次保存整单；父单 ID 由服务端固定注入，不能从用户提交的明细中转移。ID 和十进制数量在请求、响应及页面状态中保持字符串。

`MasterDetailDocument` 保留不带 `aggregateApi` 的旧单表组合能力，供尚未迁移的页面过渡使用；这一路径分别调用主单和明细 API，不提供整单原子性，不得作为新增主子业务的正式保存方式。业务服务必须限制或移除会绕过聚合事务的明细单表写入口。

页面在切厂、撤权、关闭或卸载时清理编辑状态，并忽略旧上下文请求的迟到响应。查询、保存、审核和撤销分别按实际业务权限授权；隐藏按钮不代替服务端权限检查。
