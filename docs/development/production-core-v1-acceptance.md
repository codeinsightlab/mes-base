# Production Core V1 User Acceptance Guide

使用现有 `http://localhost:5173`，选择“简单业务验收 B / SIMPLE_B”。当前验收模式 LOCAL_ONLY，只确认 MES 领料，不代表 ERP 出库或库存扣减。完整验证结果与当前阻塞见 [Verification Report](../reviews/2026-10-14-production-core-v1-verification-report.md)。

可直接查看已跑通样本：工单 `QA_CORE_V1_UI_1791966344486`（66），执行 `EXE-72`（72），领料同号（67）；路径版本99，A→B→C→E，状态 RUNNING。复验新流程请另用自己的验收编号，勿清除已有数据。

| 步骤 | 操作入口 | 预期页面与数据 | 失败时检查 |
| --- | --- | --- | --- |
| 1 创建并发布工单 | 生产基础 → 生产工单 → 新增工单；保存后“详情 / 执行”→ 下达工单 | 选择启用产品、适用已发布默认版本、正计划量；DRAFT→RELEASED | 产品/工艺是否启用和适用；是否有工单新增/下达权限；页面错误提示 |
| 2 创建 Execution | 工单“详情 / 执行”→ 新增 | 服务端生成 EXE-{id}，READY；执行目标量不等于完成量 | 工单已下达、执行新增权限、目标量；不填运行状态或时间 |
| 3 选择版本及路径 | 新增/未选路的 READY 编辑中选择实际工艺；随后“路径与开工” | 从起点逐个选择有边的下一节点，显示节点顺序及工序名称；保存完整终点路径后 SELECTED，开工不可用 | 实际版本适用于工单产品，关键节点未跳过；旧 revision 应刷新；缺名称的历史版本改选有快照的已发布版本 |
| 4 创建领料及明细 | 领料出库 → 新增单据 → 选择 EXE → 保存主单 → 下方新增明细 | 服务端固定工单/产品/实际版本；每条物料、正数量及批次分别保存；允许两个不同批次 | 主单保存成功后才能新增；关联执行与物料/单位/仓库有效；未保存修改先保存 |
| 5 提交领料 | 已保存领料主单顶部“提交领料” | 草稿保存不算提交；空明细拒绝；有效整单提交一次，忙时按钮禁用 | 路径已选择、Execution READY、主单/明细有效、issue:update 权限；查看错误提示 |
| 6 查看结果 | 同一领料页面 | “本地模式，领料已确认”，CONFIRMED；主单字段禁用，明细只读；无 ERP 主键或凭证 | SUBMITTING/SUBMIT_UNKNOWN 用“查询 ERP 状态/核实并同步”处理原操作，勿另点创建；核实需独立权限 |
| 7 确认路径已锁定 | 回工单 → 详情 / 执行 → 路径与开工 | LOCKED，有锁定时间、原节点顺序；无修改路径按钮 | 领料是否 CONFIRMED；是否仍有结果待核实；刷新当前执行 |
| 8 开工 | 路径与开工 → 开工 | READY→RUNNING；专用命令成功；普通编辑不能代替开工 | 已下达工单、有效版本、至少一张可信有效领料、无 UNKNOWN/作废中；查看后端错误 |
| 9 查看执行状态 | 关闭路径对话框，查看执行列表 | “执行中”，开始时间非空，结束时间为空；再打开路径仍 RUNNING/LOCKED | 列表刷新；确认当前 Factory 与执行编号，勿把工单目标合计当产量 |
| 10 非法编辑与作废保护 | RUNNING 的普通编辑；对应已确认领料“作废” | 编辑没有运行状态/起止时间输入，实际工艺禁用；作废确认后拒绝，不改变 CONFIRMED/RUNNING；锁路不能改或解锁 | 若有异常先保留编号/当前状态及 requestId，查看页面错误；不要删除样本或手工改库 |

QUERY 只读取外部结果；RECONCILE 根据领域结果恢复原提交，不能人工标记 ERP 成功。CONNECTED 当前没有真实厂商实现，配置为 CONNECTED 会明确失败；本轮用户页面验收使用 LOCAL_ONLY。

完成上述流程后即可反馈业务验收意见。本轮到 RUNNING 停止，报工、完工、入库不在当前交付范围。
