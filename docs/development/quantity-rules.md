# 物料数量输入与展示

## 单位与数量语义

数量规则属于当前 Factory 业务库中的计量单位。物料通过 `unitId` 使用基本单位；单据中的单位身份必须与该物料一致。当前业务不提供任意交易单位切换或隐式换算。

| 配置 | 取值 | 含义 |
|---|---|---|
| `mustBeWholeNumber` / `must_be_whole_number` | 0、1 | 为 1 时，新人工业务数量必须是整数 |
| `quantityPrecision` / `quantity_precision` | 0～6 | 新人工业务数量允许的有效小数位数 |

整数开关优先：`1 / 6` 仍只允许整数；`0 / 0` 也只允许整数。不需要通过修改已保存的数量事实来统一这两种配置。单位被引用后修改规则只影响需要按现行规则校验的新数量，不重写历史报工、入库、库存流水或冻结请求。

普通人工数量的存储边界是最多 14 位整数、6 位有效小数。`2`、`2.00` 数值等价；去尾零不等于舍入。正数、零、有符号调整量、业务上限由对应业务操作定义。例如，入库要求正量，盘亏输入正量，业务纠错允许有符号增减。

BOM 基准与组件消耗系数不是普通库存交易量。单件产品可以消耗小数个组件，不能仅因组件库存单位要求整数就拒绝该系数。BOM 展开及用料分摊保留各自已有的计算精度与舍入规则，不由输入组件修改。

## 前端使用

`mes-base-ui/src/components/business/material/QuantityInput.vue` 接收字符串 `v-model` 与可信的 `materialId`，按当前 Factory 查询物料及单位规则。数量字符串不要经过 `Number`、`parseFloat` 或固定小数位舍入。

```vue
<QuantityInput
  v-model="quantity"
  :material-id="productId"
  required
  positive
  @validity="quantityValid = $event"
/>
```

- `required` 表达必填；可选输入的空值可以是有效格式。
- `positive` 用于正向业务量。有符号纠错不设置该属性，调用方另外验证操作方向和非零要求。
- `validity` 要求当前物料规则已成功加载且输入符合所声明条件。规则缺失、读取失败、无权限或上下文变化时，调用方不得创建新命令。
- 规则读取需要 `business:material:query` 与 `business:unit:measure:query`；组件不会绕过后端授权。业务角色需显式拥有相应读取能力。
- 仅对后端允许保留原数量的元数据编辑，可传入服务端读取的 `unchanged-value`。切换物料时应取消该豁免；不能用任意输入值作为“原值”。

组件保留输入过程中的 `2.`，失焦才去无意义尾零。业务页面构造新命令时也应使用 `normalizedQuantityInput`，以覆盖直接确认的场景。已经冻结的 UUID 请求保持原内容，核实或重放时不重新格式化、不更换请求身份。

同一 Factory、会话上下文和物料的并发规则请求会去重，成功缓存有 60 秒期限，在用输入也会刷新。物料单位或单位规则更新成功后，通过 `quantityRuleInvalidation` 通知已有输入刷新；外部客户端修改通过期限刷新收敛。该缓存只改善录入体验，正式业务写入仍由后端校验。

物料切换、切厂、撤权、卸载后，旧请求结果不得回填。规则错误可局部重试；独立取得的业务事实继续显示，不用“无数据”掩盖读取失败。

## 展示与提交分离

`displayQuantity`、`quantityColumn` 和 `QuantityText` 统一去除无意义尾零，保留全部有效小数及原始值的追溯提示。展示函数不读取单位，不按单位精度截断历史事实，不改变提交数据。

| 原值 | 展示或新输入归一化 |
|---|---|
| `2.00` | `2` |
| `2.5000` | `2.5` |
| `0.000100` | `0.0001` |
| `1.234500` | `1.2345` |
| `1.234567` | `1.234567` |
| `99999999999999.123456` | `99999999999999.123456` |

金额、百分比、工时、优先级及记录数不使用物料数量规则。通用 CRUD 的所有 `decimal` 字段也不能自动视为物料数量。

## 后端与升级

Controller 的 decimal 请求绑定和响应字符串转换保持既有边界；业务 Service 负责可信物料与单位、数量方向、额度、来源、事务和幂等。正式事实写入与单据审核不能依赖浏览器已经校验。查询接口无需普遍附带 UOM 规则。

`V64__unit_quantity_rules.sql` 为每个物理业务库的 `unit_measure` 增加规则字段，既有单位默认 `0 / 6`。迁移不改写已有数量事实。迁移机制及身份核实、备份和版本校验见 [数据库升级指南](database-upgrades.md)。运行期不得因缺少迁移字段而静默猜测单位规则或回退旧流程。
