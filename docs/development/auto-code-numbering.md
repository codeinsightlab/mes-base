# 自动单据编号

自动编号由中心库服务提供。业务侧公共入口为 `AutoCodeNumbering.getDocNo(type)`；`type` 必须是“自动编码规则”页面中配置的规则编码 `ruleCode`。服务从可信的当前线程 `FactoryContext` 读取工厂 ID，调用方只传规则编码。每次调用都会分配一个新号码，因此它不是请求幂等键。业务请求重试时，应先读取已经保存的业务结果。

## 规则配置

规则及其组成在“系统 → 自动编码规则”中维护。每条规则还要选择固定字典中的单据类型：`WORK_ORDER`（工单）、`STOCK_OUT`（出库单）或 `STOCK_IN`（入库单）。新建工单仅提供工单规则；出入库单按单据方向提供对应规则。保存单据时提交所选规则编码，后端再次校验规则类别。

规则编码仍是通用入口 `getDocNo(type)` 的 `type`。单据创建服务使用带类别校验的取号入口，但调用方无需提供工厂 ID。要让规则符合工单或库存单据取号契约，按顺序配置以下三段：

规则编码长度为 1 到 64 位，只允许 ASCII 字母、数字、下划线和连字符，首位可为字母或数字。例如 `5600-` 是合法编码；不接受空格、斜杠或其他标点。

1. `FIXCHAR`：固定前缀，例如 `SO` 或 `RK`。
2. `NOWDATE`：日期格式为 `yyyyMMdd`。
3. `SERIALNO`：起始值为 `1`、步长为 `1`、启用 `DAY` 日周期，段宽至少为 `3`。

此类规则不要启用整号补齐。配置不符合契约时，服务会明确报错，不会替换成默认规则、前缀或其他标识。升级时只有已有 `WORK_ORDER` 规则会被分类为工单规则；其他历史规则保持未分类，可由管理员明确分类，不会被静默解释。

服务接口 `previewDocNo(type)` 和 `getDocNo(type)` 使用同一套配置解析与格式化，并共同校验上述契约。预览不写入计数，正式取号才会推进流水。非目标规则及组成仍保留，但调用这两个接口时会因配置不符合契约而失败。“系统 → 自动编码规则”页面上的通用预览和生成工具属于平台配置检查，不会分配工厂业务单号。业务单号由配置前缀、服务端日期和规则每日流水组成，例如 `WO20261027001`。流水段的宽度是最小宽度：`999` 之后自然变为 `1000`、`1001`。最终号码仍须符合规则最大长度和数据库结果列的 64 字符上限。

## 流水与缓存

规则配置以完整、不可变快照缓存，并按规则编码索引。快照包含全部规则及组成，不从分页 HTTP 结果拼接；组成由批量查询读取。规则或组成变更只有在中心事务提交后才会使共享快照失效。Redis 版本令牌阻止失效前启动的旧加载在失效后覆盖新快照。Redis 不可用时，服务从中心库读取当前配置，不会把缓存故障当作旧配置仍然有效的证明。

计数按规则身份、工厂 ID 和周期键分别持久化。每日业务流水使用 `rule_id + factory_id + F:<factoryId>|DAY:yyyyMMdd`。`cycle_key` 中的工厂标记也避免升级期间旧版读取器仅按规则和周期查询时与新工厂流水冲突。空工厂 ID 保留给历史/平台工具；有效业务工厂 ID 不为空。中心数据库的规则行锁会串行化多实例取号，也保护首次创建计数行。进入事务后，服务会通过数据库锁定读重新读取规则和组成；因此缓存陈旧或 Redis 失效失败都不能让停用或已变更的配置继续授权取号。规则类别与组成在同一份全局快照中，增删改或启停规则及其组成会在提交后使整份快照失效。失效失败时，新配置可能要等缓存 TTL 到期后才对缓存命中可见；正式取号仍以锁定读校验当前规则。缓存规则对象不包含可变流水状态，计数更新也不会淘汰配置缓存。日期段、日周期和生成时间共用同一个 `Asia/Shanghai` 服务端时间值。

中心库取号与后续工厂业务保存是两个事务。业务保存失败时号码可能被占用但未使用；本服务不承诺跨库事务或业务请求幂等。工单、普通出入库单及扫码投产创建的领料出库单在新建时选择对应规则；请求只传规则编码，不创建规则与单据的持久绑定。系统内部自动生成的生产入库或质量入库没有人工选择步骤，必须且只能存在一条启用的对应类别规则，否则失败。需要回显时只能按单号前缀匹配，不能据此前缀匹配结果宣称建立了持久关联。规则基本信息修改和删除使用同一前缀引用保护：先在中心事务外检查所有已绑定工厂业务库，只要存在该规则前缀开头的单据就拒绝修改或删除；没有引用时才在短中心事务锁定规则并复验规则类型及前缀后更新或删除。目标工厂库不可检查时操作失败。组成维护以完整有序规则计算前缀；若前缀会变化，先在中心事务外检查旧前缀引用（首次添加前缀时检查拟用前缀），再在短中心事务锁定规则并复验新旧前缀；已有生成号码的规则不允许改前缀，防止历史编号的配置依据丢失。分类规则若没有固定前缀，当前取号契约本身会拒绝生成；删除没有生成计数的空前缀分类规则时不按空前缀扫描整类单据；未分类且没有固定前缀的历史规则则拒绝删除，因为无法安全判定其单据引用。
