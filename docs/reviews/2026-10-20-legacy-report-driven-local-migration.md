## 2. 实施代码与中间模型

`LegacyWorkOrder / LegacyExecution / LegacyRouting / LegacyReport / LegacyDefect / LegacyMigrationBatch / LegacySourceMapping` 为独立 dataclass；转换函数与 MySQL 快照适配分开。没有从旧 Mapper 向目标 Mapper 复制表。

## 4. 计划数量与计划时间

时间规则已实现：同编号报工 create_time 的 min/max，原始记录时间语义保留。正式 `WorkOrderService.validate`（约421–425行）仅拒绝结束早于开始，**允许相等**，无需制造一秒或一天差值。

数量候选规则：对每个独立卡/路线，取首工序 `pro_material.detail`；按不同 issue_doc_no 分组，分别累计每个物料 acceptedQty，要求 qtyPer 正数且一致，取 `min(物料累计量 / qtyPer)`；再按独立流程卡求和为工单计划量候选。重复领料镜像身份、错误工序、非法JSON、负数、比率变化或目标decimal精度不满足时拒绝该候选。该值是**冻结旧领料镜像推导的历史投入候选，既不是原ERP计划，也不是当前LOCAL库存额度或新的可信投产事实**。

- 12,202 / 12,425 个Execution有投入候选（98.21%）。
- 827 / 863 张工单有完整计划量候选（95.83%）；36张未关闭计划量规则，禁止正式导入。
- 771张工单通过当前已实现的结构检查；这一数量不包含持久化身份、历史只读、质量等价及主数据授权门禁，不能称771张可导入。
- 不按所有工序报工求和；不以缺投入时的首序报工或最大报工量静默兜底。
- 冻结的工序材料余额仍有6个负 acceptedQty 项。本轮仅保留异常证据，未修为0；最终余额不充当初始投入。该异常尚未加入自动等价质量判定，相关数据仍为待核实。

当前源码证据：

1. `ProductionExecutionRules.initialize`只允许READY且start/end为空；现有Execution状态只有READY/RUNNING/COMPLETED/CANCELLED，没有历史只读身份。
2. `ProductionReportSubmitService.submit`调用 `ExecutionPathService.start`；后者约223–255行要求锁定路径、已确认领料及submission/可信外部生效证据。不能靠创建READY绕过起产。
3. 管理员 `ProductionReportService.supplement`（约67–94行）支持原人员及历史时间，但仍调用 `ProductionQuantityService.validateReportChange`。
4. `ProductionQuantityMapper.xml inputBalance`仅计算有可信issue/submission/extra的正式PRODUCTION_INPUT；没有当前领料事实时新Execution投入为0。`validateChange`约173–191行拒绝正报工超投入。因此“READY＋历史补录”也不能合法写首序2400。

## 9. 最小设计与正式 Flyway 草案（未应用）

拟议最小范围：

4. S1只读查询复用正式工单、执行、路径、报工、数量及时间线入口；必要时在既有只读详情中增加provenance/历史语义字段，不新建一套业务主链或通用CRUD。审批式历史导入为独立受控Service/运维入口，不修改普通校验含义；HTTP写接口并非必需。
5. 新目标WorkOrder/Execution/Routing/Node/Report均由目标主键分配器创建；主数据映射需审查，原人员无可信对应时保存来源快照并拒绝正式Report，不能挂迁移管理员。
6. Mapping主键本身为来源身份SHA256，符合“除主键外不擅自新增UNIQUE”的现行规则；保存原身份字段再次核对哈希冲突。不另建无约束的先查后插幂等。

并发与失败恢复设计：按工单依赖组件开启目标业务事务；先以工单归并映射主键竞争，再创建全部目标事实及逐来源Mapping，同一事务提交。竞争失败的执行者等待数据库完成竞争后核验已提交Mapping；哈希、规则或目标引用不一致报冲突，不产生第二张工单。报工Mapping主键跨批次/规则版本保持不变。异常回滚整个组件；提交后响应丢失按稳定映射回读；不同组件有界提交与检查点，不把17万报工放入一事务。批次进度只更新迁移状态，不UPDATE/DELETE原有业务事实。

上述是待确认的设计，**并发唯一、故障恢复、历史写入门禁及HTTP可读性尚未实现或验收**。S2仍须单独证明数量等价；两表和S1模型获准不自动授权S2/S3或批量。
