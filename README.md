# Base MES

面向中小型离散制造企业的轻量化生产执行与管理系统。

Base MES 围绕工单、批次和实际加工路径，连接材料领用、工序报工、不良申报、生产入库与库存追溯，帮助工厂看清正在做什么、做到哪一步、完成多少，以及材料和产品流向哪里。

本仓库为后端服务；管理与现场操作界面见 [mes-base-ui](https://github.com/codeinsightlab/mes-base-ui)。

代码托管：[GitHub](https://github.com/codeinsightlab/mes-base) · [Gitee](https://gitee.com/codeinsightlab/mes-base)

## 产品定位

适用于五金加工、机械加工、汽车零部件等离散制造场景，优先服务希望减少纸单和人工统计的中小型工厂。

- **LOCAL 独立运行**：由 MES 管理必要的生产与本地库存业务。
- **ERP 协同方向**：沿用同一套生产核心，对接 ERP 的工单和库存体系；正式库存命令仍在规划中。
- **轻量现场操作**：围绕批次扫码、完成报工和不良申报组织操作，派工按需使用。

## 底座来源与代码生成器

Base MES 的基础管理底座迁移自 RuoYi 体系，部分能力经 ktg-mes 来源项目迁入，沿用用户、组织、岗位、角色菜单、字典参数、日志、系统监控与任务调度等成熟后台能力，并适配 Java 21、Spring Boot 4 和当前前后端分离架构。生产、质量、仓储以及业务数据空间在这个基础上继续建设。

**代码生成器进行了重构。** 当前正式入口是独立的 `mes-generator` CLI，通过显式 YAML 配置读取真实数据库元数据，复用 MyBatis Generator 生成 Entity、Example、Mapper/XML，并生成配套 Spring CRUD、Vue 3 页面及菜单等可选产物。支持预览、产物选择和文件覆盖冲突检查；单表基础能力用于减少重复开发，主子关系、权限及复杂业务流程仍由业务模块实现。

因此，本项目既有明确的 RuoYi 来源，也包含面向当前架构的生成器、隔离机制和 MES 业务改造。生成器使用方式见[代码生成说明](docs/development/codegen.md)，原项目许可与来源清单见[第三方声明](docs/legal)。

| 集成基础 | OpenAPI 客户端管理、Factory 集成配置、ERP 查询与同步准备 |

## 设计亮点

- **一套系统，按工厂、业务或年度划分数据空间**：每个空间使用独立业务库，复用同一套生产核心和平台账号。既可用于多工厂，也可按“业务＋年度”组织数据。详见下方说明。
- **围绕批次追溯**：Execution 关联实际工艺路径、投入、报工、不良和入库，批次身份与扫码行为分离。
- **数量来自业务事实**：统一计算有效产出、不良损失和累计入库，支持分批入库与同批追加，避免重复计量。
- **审核驱动库存生效**：正式仓储单据审核后记录库存动作；领料入口向同一单据审核模型收敛中。
- **保留操作身份与留痕**：提交幂等、订正/作废留痕，结果不确定时明确保留状态，便于核实。

## 数据隔离不只用于多工厂

Base MES 的基础能力是“一个平台管理多个独立业务数据空间”。当前界面与模型把空间称为 Factory（工厂），使用方可以按实际管理边界配置它，并不只限于物理厂区。

| 使用场景 | 空间划分示例 | 适合的管理目的 |
| --- | --- | --- |
| 多工厂 | 一厂、二厂 | 分开维护各厂的生产与库存 |
| 按年度 | 一厂·2026、一厂·2027 | 将各年度业务记录分开保存 |
| 按业务 | 机加工业务、装配业务 | 分开维护独立业务的物料、工艺与库存 |
| 业务＋年度 | 机加工·2026、机加工·2027、装配·2027 | 同时按业务和年度组织数据 |

这些用法复用同一套代码、服务和账号平台。每个空间需要明确的Factory配置、独立业务库和授权；只配置一个空间即可服务单工厂。这里的年度划分是部署与业务组织方式，不是系统自动按日期切换数据库。

| 层次 | 管理内容 | 隔离方式 |
| --- | --- | --- |
| 平台中心 | 账号、角色、菜单、工厂、业务数据源及集成配置 | 中心库统一维护平台资料和访问规则 |
| 业务空间 | 物料/BOM、工艺、工单、Execution、领料、报工、不良及库存 | 每个空间通过Factory绑定独立业务库，业务请求按当前空间路由 |
| 用户操作 | 当前工厂、可用菜单、按钮和资源 | 后端按当前账号、角色及所选工厂校验，切厂本身不授予权限 |

例如，“机加工·2026”和“机加工·2027”可以各自有编号相同的工单、物料或库位，它们分别存在自己的业务库中。选择2026空间查看库存、报工或追溯，不会混入2027空间的数据。业务表不再重复增加 factory_id 来承担同一层隔离。

- **账号统一，授权按范围管理**：平台角色负责平台管理，也可按授权访问工厂业务；工厂角色只在所属工厂生效。同一账号可在具备相应权限的工厂之间工作。
- **切厂同步切换工作区**：前端清理旧工厂的数据、权限和相关浮层，拒绝过期响应回填；后端重新校验当前请求的工厂与业务授权。
- **事务内固定工厂与连接**：一次业务事务使用已确定的业务库，不允许处理中途切厂、切库或跨中心库/业务库混写。工厂或绑定无效时明确失败，不回退到其他工厂。
- **缓存和资源保留范围边界**：业务缓存按工厂范围隔离，私有文件继续校验所有者、范围和资源关联，不因共用平台账号而放开读取。
- **集成配置按工厂维护**：每厂最多绑定一个有效ERP；LOCAL和EXTERNAL业务继续校验原有来源，配置异常不自动降级为本地执行。

当前采用“中心库＋各业务空间独立业务库”，不是同一业务库内按租户字段共享数据。各业务库需要分别升级、备份和维护。按年度建空间时，期初库存、基础资料、未完工单及跨年在制品如何承接，仍须按正式业务规则准备；不会自动结转、自动只读封账或跨空间汇总。这也不等于各空间独立部署、独立故障域或已实现跨空间调度和调拨。实现细节见[持久化架构](docs/architecture/ADR-004-business-persistence-topology.md)与[请求准入和事务](docs/development/request-admission.md)。

## 当前阶段

项目处于开发与交付准备阶段。LOCAL 单材料生产主链已在指定测试环境完成真实业务验收，包含 BOM 比例领料、同批追加、正常品与不良品分批入库，以及审核后的执行/工单收尾。

这不代表所有业务或生产环境已验收。当前优先完善统一领料/出入库审核、请求恢复和数量查询稳定性，再补齐生产退料、调拨、现场工作站与标签、管理统计及首厂交付。

多阶 BOM 的维护能力已具备，生产投产目前只支持一条直接材料组件。部分仓储类型尚未接通正式业务来源；ERP 正式库存交易和完整委外流程尚未交付。

## 技术栈与结构

Java 21 · Spring Boot 4 · MyBatis · MySQL 8 · Redis · Flyway · Maven

采用模块化单体，按 Controller → Service → Mapper 组织业务。

| 模块 | 职责 |
| --- | --- |
| `mes-business` | 物料/BOM、生产、质量、仓储等工厂业务 |
| `mes-system` | 用户、组织、角色、菜单及系统设置 |
| `mes-framework` | 认证授权、工厂上下文、持久化路由与基础设施 |
| `mes-common` | 公共类型和工具 |
| `mes-quartz` | 任务调度与执行记录 |
| `mes-generator` | 基于数据库元数据的代码生成 |
| `mes-admin` | 应用启动、装配及数据库版本迁移 |

## 本地运行

准备 Java 21、Maven、MySQL 8 和 Redis，并将前端与本仓库配套使用。

1. 从 [`config/application-dev.example.yml`](config/application-dev.example.yml) 复制开发配置到 `mes-admin/src/main/resources/application-dev.yml`，填写自己的中心库、Redis、文件目录及数据源加密密钥。真实配置被 Git 忽略。
2. 按[平台配置与初始化说明](docs/development/platform.md)准备中心库和首个管理员；空库没有通用默认账号密码。
3. 按[数据库升级说明](docs/development/database-upgrades.md)初始化/升级目标业务库，通过平台管理建立工厂与业务数据源绑定，并配置所需权限。中心库迁移与业务库迁移是两个独立步骤。
4. 构建后，使用实际配置的端口启动：

```sh
mvn -B -ntp verify
java -jar target/mes-base-0.1.0-SNAPSHOT.jar --spring.profiles.active=dev
```

前端的 `MES_API_TARGET` 需要与后端监听地址一致。`prod` 使用对应的生产配置示例与 `--spring.profiles.active=prod`；环境准备及数据库升级须在目标环境单独核实。本地构建产物会包含本机 profile 配置，应按该环境的运行产物管理。
